## 0. 프로젝트 목적과 범위

YORBI는 AI 시대에 태어난 호기심 많은 디지털 생명체라는 **캐릭터·세계관·커뮤니티·소프트웨어 프로젝트**입니다. 토큰은 그 생태계의 한 요소로 설계하되, 토큰 발행 자체가 최종 목적이 되어서는 안 됩니다. 사람들이 계속 찾아올 이유는 캐릭터 세계관, 개발 기록, 소통, 실제 제공하는 도구와 콘텐츠에서 만들어갑니다.

**이번 개발 방향 전환:** YORBI 홈페이지의 장식/화면/부가 위젯 개선은 보류하고, 발행 가능성을 실제로 검토하고 발행 후 지속 운영할 기반 작업에 집중합니다. `crypto-moonshot-radar`는 **별도 암호화폐 탐색·분석 제품**이며 YORBI 토큰 발행 일정이나 작업 대상에 포함하지 않습니다.

현존 자산 및 한계:
- 공식 소스: `moogun-jeong/yorbi-world` — 캐릭터 웹사이트와 Explorer/Safety Scan/Wallet Radar 일부 베타 기능. **YORBI 자체 토큰 아님.**
- 공개 사이트: `https://yorbi-world.arhyme.workers.dev/`.
- 공식 X: `https://x.com/MeetYorbiAI`.
- YORBI Talks는 **계획**, 라이브 AI 에이전트 아님.
- Discord/Telegram/토큰 커뮤니티 운영 채널은 지금 확인된 공식 채널이 아니므로, 만들기 전에는 존재한다고 홍보하지 않음.
- 마케팅의 기준은 실제 제작한 콘텐츠·기능·운영 증거. 인위적 거래량·가짜 팔로워·거짓 파트너십·가짜 상장 발표 금지.

## 1. 단계별 출시 로드맵 — 상대 일정과 승인 게이트

| 단계 | 주요 산출물 | 완료·진행 조건 |
| --- | --- | --- |
| **G0 — Genesis (진행 중)** | 브랜드/캐릭터 공식성, 소스·X·사이트, 커뮤니케이션 원칙, 개발 공개 이력 | '미발행' 표기 유지, 가짜 컨트랙트/사전판매 신고 경로, 콘텐츠 톤 확립 |
| **G1 — Token Design (다음 우선순위)** | 체인·토큰 표준 비교, 실제 토큰 기능, 공급량·배분·베스팅, 개발자·커뮤니티·LP·운영 준비금 배분표, 법률·예산 검토 | 사용자 승인된 Token Spec v1.0, 법률 리스크와 예상 비용 공개, 가짜 토큰·심볼 중복 확인 |
| **G2 — Testnet & Security** | 최소 컨트랙트/SPL mint 테스트, 권한·배포·전송 테스트, 제3자 위험 도구 점검, 소스 검증, 배포·LP 운영 런북 | 위험 권한 설명 가능, 테스트넷 결과·실패 원인 기록, 키·복구/서명 보안 확인 |
| **G3 — Mainnet Genesis** | 실제 배포(사용자 최종 승인 후), 정확한 Chain + Contract/Mint, 공식 Explorer 링크, 공급·분배 증거, 위험 권한 및 LP 구조 공개 | 온체인 실제 거래 검증, 공식 계정의 동일 주소 공지, 컨트랙트 중복/사칭 점검, LP 안전 체크리스트 |
| **G4 — First 30 Days** | 투명 운영 주간 보고, LP·보유 집중도·재무 변동 추적, 커뮤니티 온보딩, 캐릭터/제품 개선 | 공지한 배분·베스팅 준수, 정해진 운영 주기, 보안 신고 대응 |
| **G5 — Days 31–90** | 실제 사용자 반응 반영, 공개 변경 이력, 첫 기능 릴리스/콘텐츠 시리즈, 운영비와 지속성 검증 | 작동하는 기능·참여 지표로 평가. 가격 목표·CEX 상장을 성공 기준으로 쓰지 않음 |
| **G6 — Ongoing** | 분기별 로드맵 재평가, 거버넌스·재무 공개, 제품 실험·장기 커뮤니티 운영 | 이행 가능한 약속만 발표, 중단/방향 변경 시 이유 공지 |

**중요:** G1→G2→G3는 자동 진행이 아닙니다. 메인넷 배포·유동성 투입·잠금·커뮤니티 배분 등의 온체인 행동은 실제 자금 지출과 되돌리기 어려운 위험을 수반하므로, 건별 검토·최종 승인 이후에만 실행합니다. 출시 날짜는 준비가 끝난 다음 공개합니다.

## 2. G1 토큰 설계: 미결정 사양과 결정 방법

| 결정 항목 | 현재 | G1 산출물 |
| --- | --- | --- |
| 프로젝트명 | YORBI | 공식 표기·심볼 중복 확인 |
| 티커 | 미확정(가칭 YORBI) | 정확한 ticker 및 외부 중복/사칭 검토 |
| 체인/표준 | 미정 | Base / BNB Chain / Solana 등 기술·비용·사용자/DEX 접근성 비교, 하나 선택 |
| 총공급량·decimals | 미정 | 고정 공급 또는 명확한 발행 권한 정책 |
| 컨트랙트 권한 | 미정 | Mint/Freeze/Blacklist/Tax/Proxy/Owner 역할의 존재·필요성·폐기 계획 |
| 유통/배분 | 미정 | 운영·커뮤니티·팀·유동성 준비금 비율 합계 100%, 주소·베스팅·공시 방식 |
| LP 초기 조성 | 미정 | 거래쌍/DEX, 투입 비용, 예비 자금, LP 소유·잠금/소각 방식과 리스크 |
| 운영 지갑 | 미정 | 개인 핫월렛/금고 분리, 복구 방법, 공개 가능한 주소, 지출 승인 방식 |
| 수요·유틸리티 | 초안 필요 | 공개 캐릭터/커뮤니티/실제 기능과 연결되는 합리적 사용처; 필요 없으면 토큰 유틸리티를 허위로 만들지 않기 |
| 법률/세무·홍보 | 검토 전 | 거주지/판매 대상/공개모집 여부/운영 주체 관련 전문가 검토 및 준수 체계 |
| 출시비용 | 미정 | 배포 가스, DEX LP, 테스트·감사, 운영비, 사고 대비비용을 별도 산정 |

설계 원칙: **치명적인 Mint/Honeypot/판매 제한/숨은 수수료/LP Rug 구조를 채택하지 않습니다.** 임의의 토큰 가격 방어·수익률 목표·상장 약속을 만들지 않습니다. 팀/운영 보유분을 0이라고 가장하지 않고 실제 비율과 주소 및 락업 일정을 정직하게 공시합니다.

체인 선택의 기준은 단순 최저 가스비가 아니라 *토큰 생성·거래·공식 탐색기 검증·LP 운영의 전체 비용과 장기 운영 난이도*입니다. '초기 유동성에서 팀 투자비 절반 회수' 같은 계획을 기본값으로 삼지 않고, 실제 유통량·팀 매각 조건·시장 영향과 공개 일정을 먼저 정합니다.

### G1 출고 필수 문서

1. `TOKEN-SPEC-v1.md`: 체인, 공급, decimals, 컨트랙트 권한, 동결/세금, 팀/커뮤니티/LP 배분을 확정 수치로 표기.
2. `TOKEN-RISK-REGISTER.md`: 보안·사칭·운영지갑·법률·LP·유동성·커뮤니케이션 리스크, 대책/담당자/재검토일.
3. `GENESIS-RUNBOOK.md`: 테스트넷→보안 게이트→메인넷 배포→Explorer 검증→LP 조성→공식 공지→사고 대응 순서.
4. `TOKEN-DISCLOSURES.md`: 투자 위험, 운영 지갑/배분, 제한사항, 수정/변경 공지, 사칭 경고.

위 문서는 아직 **미완성/미승인**입니다. 파일이 생성되거나 표에 입력됐다는 이유로 토큰 발행을 승인하거나 확정 사양으로 간주하지 않습니다.

## 3. 출시 전·당일(T0)·출시 후 통제

**T-30~T-7 (준비):** 컨트랙트 테스트, 공급량·권한·자산 분배 확인, 테스트넷/실패 사례 보존, 사칭 토큰/도메인 검색, 배포 지갑 운영 방안, 예산 상한, 사용자 승인, 공식 게시 초안의 체인+컨트랙트 정확성 검증. 법률 검토 전에는 판매나 투자자 모집을 진행하지 않음.

**T-7~T-1 (출시 게이트):** 컨트랙트 소스 검증과 공급량 확인, 예상 초기 유동성/슬리피지 시나리오, LP 토큰 보관/락업/소각 조건 검증, 긴급 연락/대응 시나리오, 체인·주소 동일성의 독립 이중 확인. 어떤 주요 위험도 해결하지 못하면 날짜를 미룸.

**T0 (메인넷):** 실제 트랜잭션 성공 → 체인 탐색기에서 최종 컨트랙트와 총공급량·권한 검증 → 유동성 공급 증거 확인 → 정확한 공식 주소를 동일한 X/웹사이트/README 공지에 반영. 아직 하지 않은 DEX 유동성 조성이나 상장을 한 것처럼 표현 금지. 사용자 승인 없는 자금 이동·거래 없음.

**T+1~7:** 매일 이상 권한·LP 상태·거래 실패·사칭 신고·계정 침해·커뮤니티 질문을 확인. 계획된 베스팅 외 팀 물량 이동 시 변경 근거를 공시.

**T+8~30:** 주 1회 보유/유동성/재무/제품 진행 상황을 업데이트하고, 실제 기능·콘텐츠를 제공. 거래량 부풀리기, 자기거래, 유료 홍보 은폐, 근거 없는 FOMO 조성 금지.

**T+31~90:** 유지 가능한 주간 운영으로 전환하고, 기능/콘텐츠 기여와 참여를 측정해 다음 분기 계획을 공개. 거래소 상장은 사전 승인·공식 공지 확인 전까지 예측 또는 희망사항으로만 분리.

## 5. 커뮤니티와 X: 캐릭터 스토리 기반의 출시 전 성장

주력 공식 채널은 **X @MeetYorbiAI**. 초기에는 무료 X 계정의 글 길이 제한과 게시 후 수정 어려움을 고려해 **12~15개의 품질 검수된 포스트**로 계정의 정체성을 구축합니다. 이 구간은 즉흥적 홍보나 가격 예측이 아니라 **세계관 → 제작 과정 → 도움 되는 정보 → 투명한 발행 준비 과정** 순서입니다.

- 글은 짧고 명확하게, 링크·주소·오탈자 사전 점검. 미출시 기능은 'planned'로 표기.
- 캐릭터의 말투와 브랜드 목소리를 일관되게 유지; 한국어·영어 사용 목적이 명확할 때에만 병기.
- 제품/토큰 관련 공지는 기능이나 실제 컨트랙트 트랜잭션을 확인한 뒤 게시.
- 출시 뒤에는 과잉 게시보다 주 2~3회의 개발 기록·캐릭터 콘텐츠와 주간 운영 투명성 보고가 우선.
- 일방적 가격 홍보보다 실제 피드백/질문 응답, 콘텐츠 반응과 재방문을 관찰.
- 유료 광고/협업이 생길 경우 상업적 관계를 공개. 비공식 계정·DM 투자 요청 금지.

구체적인 15개 게시 주제와 게시 전 체크리스트는 `docs/YORBI-X-CONTENT-PLAN.md` 참조. **게시·팔로우·DM 발송은 사용자가 실행을 승인하기 전 자동으로 하지 않음.**

## 6. 지속 개발: 사이트 꾸미기보다 운영 가치

1. **Genesis 투명성 도구**: 개발/토큰 발행의 상태, 공식 컨트랙트의 검증된 근거, 운영 변경 이력(발행 후).
2. **YORBI Explorer 안정성**: 기존 베타의 오류·출처 정직성 유지. 사용자에게 실제 도움이 되는 보안/자산 이해를 우선하며 홈페이지 레이아웃 수정을 목표로 삼지 않음.
3. **YORBI 세계관 콘텐츠**: 짧은 탐험 에피소드, YORBI의 질문, 캐릭터의 성장 이야기, 실제 기능 개발 기록을 연결.
4. **YORBI Talks**: 실사용 니즈, 운영비, 개인정보·AI 응답 신뢰성 검토 후 별도 실험. 미출시 기능을 토큰 투자 근거로 내세우지 않음.
5. **사용자 커뮤니티**: 실제 활동 인력이 확보되면 채널/규칙/스캠 대응 프로세스를 설계. 채널 수 자체보다 지속 대응 가능성이 중요.

## 7. 소유권·비용·출시 결정 정책

- 프로젝트 소스와 문서 개발은 GitHub PR과 리뷰로 진행 가능. **토큰 배포, LP에 자금 예치, 권한 포기/변경, 토큰 배분, 팀 물량 판매, 유료 광고 및 X 실제 발행**은 개별적인 승인 게이트가 필요.
- 시드 문구·개인키를 GitHub, 채팅, 배포 환경변수에 올리지 않음. 로컬 테스트 계정과 실제 자금 지갑을 구분.
- 월별 비용을 기획·가스·LP·보안/검증·운영·마케팅으로 분리. 무료/극소 비용 원칙을 우선하지만 초기 LP는 실제로 자금 손실 가능성이 있음을 명시.
- 누구든 프로젝트와 동일한 이름/심볼을 먼저 발행할 수 있으므로 심볼은 공식 컨트랙트 확인 없이 신원 증거로 쓰지 않음.
- 법률·회계 판단을 개발자가 확정하지 않으며 공개 판매·투자금 모집·리워드 배분 전에 해당 지역 전문가 검토를 실시.
